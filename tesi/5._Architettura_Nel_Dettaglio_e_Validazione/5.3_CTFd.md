# 5.3 Plugin CTFd

CTFd è una delle piattaforme open source più diffuse per la gestione di competizioni Capture The Flag. Nativamente, CTFd è progettato per sfide di tipo *Jeopardy*, in cui la risoluzione coincide con l'invio di una stringa alfanumerica statica o regex (la *flag*).

Per abilitare gare di tipo *Defense* o *Patching*, in cui l'obiettivo del team consiste nel mettere in sicurezza un servizio vulnerabile mantenendone la piena operatività, è stata sviluppata un'estensione per CTFd composta da due moduli integrati: `patch_challenges` e `patch_flags`. Il plugin agisce da intermediario tra l'interfaccia web della competizione e le API REST esposte da BlueAgent.

> CTFd usa Flask al posto di FastAPI (adottato in BlueAgent) ed usa SQLAlchemy per gestire facilmente il modello dei dati utilizzato nel codice.

## 5.3.1 Componenti del Plugin: PatchChallenge e PatchFlag

L'integrazione sfrutta l'architettura a plugin di CTFd estendendone le classi base:

* **`PatchChallenge`**: definisce una nuova tipologia di sfida. Ha un modello dei dati per facilitare l'integrazione con il database di CTFd. Questo modello memorizza la specifica dichiarativa della topologia in formato JSON/YAML e l'insieme dei comandi di verifica da inoltrare a BlueAgent.
* **`PatchFlag` (`BaseFlag`)**: invece di confrontare una stringa inserita dal giocatore con un valore memorizzato nel database, il metodo `compare()` interroga l'Oracolo (BlueAgent) e registra il tentativo di verifica ed il suo esito.

## 5.3.2 Distribuzione delle Configurazioni WireGuard
Per permettere ai partecipanti di operare sui container della propria challenge, il plugin gestisce automaticamente l'accesso alla rete del team:
1. Il plugin espone all'interfaccia web le rotte per la gestione della connettività.
2. Quando un utente autenticato visualizza la sfida o richiede l'accesso, CTFd invoca `PUT /teams/{team_k}/members/{user_id}` di BlueAgent.
3. BlueAgent alloca dinamicamente un indirizzo IP libero all'interno della subnet VPN del team (`10.k.0.0/24`), genera la coppia di chiavi asimmetriche e registra il peer sull'interfaccia WireGuard.
4. Il plugin restituisce al browser il file di configurazione WireGuard (`.conf`) pronto per l'importazione.

## 5.3.3 Flusso di Verifica e Convalida

Il ciclo di verifica e attribuzione del punteggio si articola nelle seguenti fasi:
1. **Richiesta di verifica**: il giocatore, dopo aver applicato le contromisure sui file e sui servizi del container, preme il pulsante di verifica sull'interfaccia di CTFd.
2. **Inoltro all'Oracolo**: CTFd invia una richiesta `POST /teams/{team_k}/verificator` a BlueAgent, trasmettendo l'identificativo del team e la specifica della challenge.
3. **Esecuzione**: BlueAgent esegue la verifica in ambiente separato.
4. **Aggiornamento punteggio**: BlueAgent restituisce il verdetto a CTFd che si occupa di aggiornare i punteggi.
