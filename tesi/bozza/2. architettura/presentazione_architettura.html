Ottimizzazione

SNAT Masquerade: Accesso controllato a Internet per i container tramite la scheda WAN fisica.

2. Regole nftables & Avvio Container

Filtering & Incus Profile
bash • nftables & launch
# Tabella inet blueagent e TCP MSS Clamping per evitare frammentazione $ sudo nft add table inet blueagent $ sudo nft add chain inet blueagent forward '{ type filter hook forward priority 0; policy accept; }' $ sudo nft add rule inet blueagent forward tcp flags syn / syn,rst tcp option maxseg size set rt mtu # Masquerade NAT per accesso internet dei container $ sudo nft add chain inet blueagent postrouting '{ type nat hook postrouting priority 100; policy accept; }' $ sudo nft add rule inet blueagent postrouting ip saddr 10.0.1.0/24 ip daddr != 10.0.1.0/24 masquerade # Crea profilo Incus e avvia il container live su pool ZFS $ sudo incus profile create team-0-profile $ sudo incus profile device add team-0-profile eth0 nic nictype=bridged parent=br-team-0 name=eth0 $ sudo incus launch ubuntu:22.04 c0-web -p default -p team-0-profile -s blueagent-zfs

01
Zero Side-Channel Leakage

Esecuzione dei test su cloni isolati in una rete OVN inaccessibile. Impossibile per i partecipanti intercettare exploit, payload o flag tramite sniffing o ispezione processi.

02
Nessun Impatto sulla Produzione

Exploit instabili o test distruttivi non alterano lo stato né causano crash dei container live, preservando l'SLA di uptime e il lavoro salvato dalla squadra.

03
Fedeltà Topologica Assoluta

I container mantengono le stesse interfacce di rete, gli stessi IP statici (10.k.1.x) e lo stesso gateway sia in produzione che in fase di verifica.

04
Ambiente Stateful Completo

Superamento dei limiti di kCTF (nsjail/OCI): supporto nativo a container con systemd, file di log persistenti e architetture multi-tier realistiche.

Critica & Limiti Architetturali

Trade-offs & Roadmap
⚠️
UDP Path MTU Blackhole

WireGuard (MTU 1420) e Geneve (MTU 1442) riducono l'MTU: pacchetti UDP di grandi dimensioni con flag DF possono essere scartati.

⚠️
Limite Scalabilità a 254 Team

Indirizzamento deterministico 10.k.x.x confina k a un singolo byte (0..254), limitando la capacità per host a 254 team.

⚠️
Concorrenza Mononodo

Il lock TwoTierLock è vincolato al singolo host locale; per scalare su cluster multi-nodo occorre un broker distribuito (es. Redis).
