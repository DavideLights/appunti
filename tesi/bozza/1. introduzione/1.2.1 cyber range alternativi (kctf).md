## kctf
**fonte**: https://google.github.io/kctf/, https://github.com/google/nsjail/

E' una piattaforma basata su **Kubernetes** per gestire competizioni CTF.

> Kubernetes: sistema per automatizzare il deploy, scalare e gestire applicazioni containerizzate. Rollback dei cambiamenti automatizzato in caso di errore, serivce discovery incorporato e altre cose...

L'architettura prevede:
* un cluster, che contiene un'insieme di challenge
* dei deployment, ognuno contiene un'insieme di container
	* un container e' dedicato per l'healthcheck
* una challenge e' un deployment in **kubernetes**

Ogni challenge prevede l'uso di **nsjail**: viene eseguito un fork ad ogni connessione TCP, fornendo all'utente un'ambiente separato su cui eseguire i processi. Dunque, lo stesso conteainer puo' essere riutilizzato da piu sfidanti.

il mount del file system e' regolato da file di configurazione, l'esempio seguente monta la radice in sola lettura:
```conf
mount {
  src: "/"
  dst: "/"
  is_bind: true
  rw: false
}
```

con `seccomp_string` e' possibile specificare le chiamate da abilitare: 
```bash
seccomp_string: "ALLOW { read, write, exit, exit_group } DEFAULT KILL"
```

**Problemi**:
* in nsjail il filesystem e' disponibile in sola lettura. Comandi come `apt` e modifiche diretta a `/etc` non funzionano.
* se la connessione TCP cade allora tutto il lavoro che risiede in RAM e' perso
* in nsjail, l'applicazione di filtri seccomp potrebbero impedire l'esecuzione di alcune chiamate di sistema.
* kCFT usa Kubernetes introducendo costi e complessita.
