# 2. Tabella Sinottica dei Casi d'Uso di Sistema

La seguente tabella riassume i Casi d'Uso formali del sistema BlueAgent, strutturati secondo i principi dell'Ingegneria del Software (Cockburn / UML). Ciascun caso d'uso rappresenta un'interazione completa a valore per un attore primario esterno, con tracciabilità puntuale verso i Requisiti Utente (`UR`) e di Sistema (`SR`).

| ID          | Titolo Caso d'Uso                                           | Attore Primario             | Ambito / Interfaccia Operativa (API)                                                                                                                                                                                                           | Requisiti Tracciati                                                                                                       |
| :---------- | :---------------------------------------------------------- | :-------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------ |
| **`UC-01`** | **Provisioning e Gestione Connettività Team**               | Piattaforma CTFd            | `POST /teams`, `POST /teams/{k}/members`, `GET /teams/{k}/members/{id}/config` (allocazione hole-filling `10.k.0.x/32`, chiavi Curve25519/PSK, bridge `br-team-k`, interfaccia kernel `wg-k`, nftables `@team_links`)                          | `UR-ACC-01`, `UR-ORG-01`, `SR-NET-01`, `SR-NET-02`, `SR-CON-01`                                                           |
| **`UC-02`** | **Distribuzione Dichiarativa e Attivazione Sfida (Deploy)** | Piattaforma CTFd            | `POST /challenges` (schema `ChallengeConfig`, allocazione cgroups v2 `limits.cpu`/`limits.memory`, iniezione IP statico deterministico `10.k.1.x`, readiness probes sequenziali con rollback atomico)                                          | `UR-CHL-01`, `UR-CHL-02`, `UR-CHL-03`, `UR-CHL-04`, `UR-ORG-01`, `SR-ENG-01`, `SR-ENG-05`, `SR-CON-01`                    |
| **`UC-03`** | **Esecuzione Verifica Automatica su Dark Sandbox OVN**      | Piattaforma CTFd            | `POST /challenges/{id}/verify?team_k={k}` (clonazione istantanea ZFS CoW $\le 100\text{ ms}$, switch Geneve L2 OVN effimero `verify-*`, dual-mode verification white-box `container` e black-box `verifier`, teardown LIFO garantito via RAII) | `UR-VER-01`, `UR-VER-02`, `UR-VER-03`, `UR-VER-04`, `UR-ORG-01`, `SR-HST-02`, `SR-NET-03`, `SR-NET-04`, `SR-VRF-01`..`05` |
| **`UC-04`** | **Dismissione Risorse e De-provisioning (Teardown)**        | Piattaforma CTFd            | `DELETE /challenges/{id}/teams/{k}`, `DELETE /teams/{k}` (smantellamento mirato container di sfida o rimozione integrale interfaccia `wg-k`, regole nftables, bridge `br-team-k`, cascade cleanup database SQLite)                             | `UR-ORG-01`, `UR-ORG-03`, `SR-ENG-01`, `SR-NET-01`, `SR-NET-02`, `SR-CON-01`                                              |
| **`UC-05`** | **Ispezione Stato, Telemetria e Diagnostica di Sistema**    | Piattaforma CTFd / SysAdmin | `GET /challenges`, `GET /teams/{k}/peers`, `GET /health` (telemetria live peer kernel WireGuard `wg show dump`, mappature di allocazione sfide e probe di liveness del socket Incus e background scheduler)                                    | `UR-ORG-01`, `UR-ORG-02`, `SR-CON-01`, `SR-CON-04`, `SR-ENG-02`                                                           |
| **`UC-06`** | **Compilazione e Import Immagini Base (Build Pipeline)**    | Autore Sfida / CTFd         | `POST /images`, `GET /images` (ricezione manifesto YAML Distrobuilder, prenotazione atomica CAS Write-Ahead, build asincrona `--type=unified`, import automatico nello storage pool Incus con caching SHA-256)                                 | `UR-CHL-01`, `SR-IMG-01`, `SR-ENG-01`                                                                                     |

### Mappatura delle Attività Non-Sistema ed Esterne

A fini di rigore metodologico, la tabella seguente documenta come le attività precedentemente catalogate come casi d'uso siano state correttamente riposizionate nell'architettura dei requisiti:

| Attività Precedente | Natura Effettiva | Collocazione Corretta |
| :--- | :--- | :--- |
| *Accesso ai container live (`ex UC-P02`)* | Attività utente finale (User Task) | Resa possibile da `UC-01` e `UC-02`; traffico di rete L3/L2 diretto via WireGuard. |
| *Applicazione patch difensive (`ex UC-P03`)* | Attività utente finale (User Task) | Modifica del rootfs all'interno del container tramite shell remota (SSH/TTY). |
| *Consultazione esito su CTFd (`ex UC-P04`)* | Interazione con sistema a monte | Interfaccia UI della piattaforma CTFd; CTFd interroga BlueAgent tramite `UC-03`. |
| *Progettazione dichiarativa YAML (`ex UC-A01`..`A05`)* | Attività di specifica offline (IaC) | Sottomessa ed eseguita da CTFd tramite il caso d'uso `UC-02`. |
| *Bonifica sandbox orfane (`ex UC-S02`)* | Comportamento interno del sistema (Self-Healing) | Requisito di sistema non-funzionale `SR-CON-03` / `UR-ORG-03` garantito da `LifecycleManager`. |
| *Bootstrap del nodo host (`ex UC-S01`)* | Procedura di deployment DevOps | Script di installazione `host_setup.sh` (`SR-HST-01`..`04`), propedeutico all'avvio. |
