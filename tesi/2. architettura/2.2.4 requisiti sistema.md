## Categoria SR-HST: Host & Piattaforma di Esecuzione

| Codice | Componente | Descrizione Tecnica | Riferimento Codice |
| :--- | :--- | :--- | :--- |
| **SR-HST-01** | OS & Moduli Kernel | Supporto target Debian 13 (Trixie) con kernel Linux moderno comprendente moduli WireGuard, cgroups v2 e supporto `nftables` con IP Forwarding abilitato (`net.ipv4.ip_forward=1`). | `scripts/host_setup.sh#L43-L49` |
| **SR-HST-02** | Storage Pool CoW | Configurazione di uno storage pool Incus su ZFS (o Btrfs) denominato `blueagent-zfs`, capace di clonare container istantaneamente a livello di blocchi. | `src/blueagent/config.py#L11`, `agent/specification.md#L26` |
| **SR-HST-03** | Demoni SDN Host | Presenza attiva di Open vSwitch e OVN (`ovs-vswitchd`, `ovsdb-server`, `ovn-northd`, `ovn-controller`) con listener TCP su `tcp:127.0.0.1:6641` per Incus. | `scripts/host_setup.sh#L57-L69` |
| **SR-HST-04** | Uplink Parent Bridge | Il bridge di sistema `incusbr0` deve dichiarare un intervallo di subnet allocabili OVN (`ipv4.ovn.ranges`) per connettere a monte le reti logiche effimere. | `scripts/host_setup.sh#L76-L84` |

## Categoria SR-NET: Rete Ibrida, Routing & Traffico

| Codice        | Componente                      | Descrizione Tecnica                                                                                                                                                                 | Riferimento Codice                          |
| :------------ | :------------------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------ |
| **SR-NET-01** | Tunnel WireGuard L3             | Per ciascun team $k$, creazione dell'interfaccia `wg-k` su subnet `/30` (`10.k.0.1/30`) con Cryptokey Routing associato alla chiave pubblica del team (`AllowedIPs = 10.k.0.2/32`). | `src/blueagent/network/manager.py#L74-L103` |
| **SR-NET-02** | Linux Bridge L2 Live            | Per ciascun team $k$, allocazione di un bridge kernel `br-team-k` con IP `10.k.1.1/24`, associato a un profilo Incus `team-k-profile` per l'aggancio diretto delle `veth`.          | `src/blueagent/network/manager.py#L58-L72`  |
| **SR-NET-03** | Overlay OVN Dark Sandbox        | Per ogni verifica, creazione di una rete SDN OVN effimera (`verify-{session_id}`) su tunnel Geneve con isolamento totale dal traffico di produzione.                                | `src/blueagent/verifier/ovn.py#L37-L50`     |
| **SR-NET-04** | Fedeltà Topologica & IP Overlap | Coesistenza simultanea della medesima subnet (`10.k.1.0/24`) e della singola scheda `eth0` sia in live che in sandbox, senza conflitti di routing sull'host.                        | `agent/specification.md#L186-L198`          |
| **SR-NET-05** | TCP MSS Clamping                | Applicazione della regola nftables `tcp flags syn / syn,rst tcp option maxseg size set rt mtu` nella tabella `inet blueagent` per azzerare il fenomeno dell'MTU Blackhole.          | `src/blueagent/network/nftables.py#L11-L26` |
| **SR-NET-06** | NAT Masquerade                  | Configurazione del mascheramento postrouting nftables per la rete `10.0.0.0/8` verso l'uscita WAN dell'host.                                                                        | `src/blueagent/network/nftables.py#L27-L32` |
